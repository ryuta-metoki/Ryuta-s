## 3. 部署と担当(25体)
どの部署も、戦略 → リサーチ → 執筆 → 編集 → 配信の順に1体ずつ処理し、前の体の出力だけを読む。

| 部署 | 戦略 | リサーチ | 執筆 | 編集 | 配信 |
|---|---|---|---|---|---|
| 発信 | 角度・フック・ブリーフ・書かないこと | 一次情報5件以内・事実・反証3件 | note・Xのフルドラフト | 30%削減・フック・締め・変更ログ | note / X / メール / Slack に整形 |
| 営業 | なぜこの顧客にこの提案か | 顧客サイト・公開資料・競合 | 提案書本文・商談メール | 1ページ要約・スライド5枚の要点 | PDF・メール・Slack用(送信しない) |
| サポート | 問い合わせの分類・返信方針 | KB・過去の類似チケット | 返信下書き | 100字以内・ブランドボイス | チケット形式・KB更新差分(送信しない) |
| リサーチ | 今週の3つの問い | 動向・業界レポート・公開データ | 週次レポート | 要点絞り | Slack用・Notion更新差分(投稿しない) |
| 経営判断 | 今月のリスク3点 | 指標・市場データ | 意思決定メモ | 要点3点(各100字以内) | Notion追記・Slack共有文(最終判断は社長) |

### 使える道具(担当ごと)
- 戦略: ファイルの読み書き、コマンド実行、検索。
- リサーチ: 上に加えて、Web検索とWebページの取得。
- 執筆: ファイルの読み書き、検索。
- 編集・配信: ファイルの読み書きのみ。

### できないこと(全体共通)
- 外部への送信・投稿・公開は一切しない(メール送信、X・noteへの投稿、Slack投稿など)。下書きまで。
- 入力が足りない、または判断が必要なときは推測で埋めず、止まって社長に確認する。
- 編集担当は、角度とリサーチを見ない(草稿だけを読む)。

### 社長に確認が上がる場面
- 返金・契約撤回・法務の判断(サポート)。
- 経営判断の最終結論(経営判断)。
- 入力不足で止まったとき(全部署)。

## 4. 気づいたこと
- 毎朝レポートが毎日「対応不要」の同じ内容で、通知も毎日届いている。依頼が入るまでは、通知は不要かもしれない。
- 依頼の自動処理は毎時動いているが、依頼がないと何もしない。毎時のセッション起動が無駄になっている可能性がある。
- 最初の実依頼を1件入れて5体を通すことが、いまの最優先。blueprint の「作るもの」より先に、実際に回るかを確かめたい。
