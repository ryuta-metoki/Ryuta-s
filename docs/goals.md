# やりたいこと(目的と進め方)

## 目的
1. noteとX(自分のアカウント)で継続的に発信する。
2. まだ商品・サービスはない。発信を読んでくれた「少し興味のある人」から、街頭インタビューのように読者の悩み・困りごとを聞き、事業の種を見つける。
3. 見つけた悩みを事業(サービスとは限らない)に落とし込む。

## 流れ(段階ごとに強さを上げる)
| 段階 | 読者の行動 | こちらがすること | 状態 |
|---|---|---|---|
| 1. 興味 | Xで投稿を見る | Xスレッド・単発投稿で入口を作る | 今ここ |
| 2. 読む | noteを読む | note末尾で「別のnote・Xを読み進める」導線だけ置く | 今ここ |
| 3. 一言 | 悩みを一言返す | note末尾かXに「いま一番困っていること」を一問だけ置く | 次 |
| 4. 話す | 15分だけ話す | 一言をくれた人に、街頭インタビュー風の短い対話を頼む | 次の次 |
| 5. つながる | LINE公式に登録 | 継続して悩みを聞く場所として案内 | まだ決めない |

- noteを読んだ直後の行動は、いまは「別のnote・Xを読み進める」だけを求める(強い誘導はしない)。
- 発信の目的は売ることではなく、悩みを聞ける関係を増やすこと。

## 運用ルール
- 投稿は下書きまで自動。公開(X・note)は社長が自分で行う。
- 読者の悩みは、個人が特定されない形で `reports` / `runs` にまとめ、毎週のレポートで傾向を見る。

## 全体像
決定事項と作るものの全体は `docs/blueprint.md` にまとめた。この文書は目的と流れだけを示す。

## 決まっていないこと(旧。blueprint.md で確定済み)
- 悩みの「一言」を、どこで受け取るか(Xの返信 / noteのコメント / フォーム / LINE)。
- インタビューを頼む相手の絞り方と、お礼の有無。
- 事業の形(サービス / コミュニティ / 情報発信 / その他)の判断基準。
- LINE公式を使い始める時期と、登録の理由づけ。
