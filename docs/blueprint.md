# 全体像(確定版)

作り始める前に、決めたことをすべて1か所にまとめる。変更したい点があれば、ここを直してから作る。

## 1. 何をやるか
商品はまだない。note と X で発信し、読者の悩みを聞いて、事業の種を見つける。見つけた悩みは、基準(7)を満たしたら事業に落とし込む。

## 2. 発信
| 項目 | 決定 |
|---|---|
| 素材の元 | 仕事で読む資料・記事全般 |
| 3本柱 | 柱1 学んだこと(インプット) / 柱2 意識していること(仕事のやり方) / 柱3 思いついた事業アイデア |
| 読者像 | インプットが多い人全般(職種は問わない) |
| 頻度 | note 週2本 + X 毎日 |
| 公開 | 下書きまで自動、公開は社長が行う |
| 末尾の導線 | 別のnote・Xを読み進める + 任意で一問 |
| 一問の文言 | 学んだことを仕事に活かせず困ったことは? |

- 3本柱は、1週間に柱1を2本、柱2か柱3を1本以上を目安に回す(仮)。
- 柱3(事業アイデア)の記事は、アイデアへの反応も悩みの声として集める。

## 3. 声の受け取り
- 受け取り口: X の返信・DM。
- 保管: ダッシュボードのDBとリポジトリ。相手のハンドルは判別コードに置き換え、個人が特定されない形で保存する。
- 記録する項目: 日付 / 経路(返信・DM・インタビュー) / 判別コード / 悩みの一言(原文) / 属性メモ / 悩みのタグ / インタビュー状況。

## 4. インタビュー
- 相手: 一言をくれた人すべてに頼む。
- お礼: なし(感謝のメッセージのみ)。
- 形式: 15分、チャット可。質問の型と記録テンプレートは `docs/street-interview.md`。
- 依頼文はDMの下書きとして作り、送信は社長が行う。

## 5. LINE公式
- 声が10人分集まってから使い始める。それまでは作らない。
- 10人分に達したら、ダッシュボードの「いま社長がやること」とスマホ通知で知らせる。

## 6. 全体の流れ
```
X投稿(毎日) → note(週2本) → 一言を返す(X返信・DM) → 15分の対話 → 悩みを集計
                                                                  ↓
                                          10人分で LINE開始 ／ 基準を満たせば事業化を検討
```

## 7. 事業にするかの判断基準(4つ)
次を、集めた声と記録から確認する。
1. 同じ悩みが複数人から出る(目安: 声10人中3人以上、仮)
2. いま実際に時間やお金をかけている
3. 自分がやりたい・得意なこと
4. 仕組み化すれば1人で回せる

- 1と2は、記録から数える。3と4は、社長が判断する(エージェントは材料を出すだけ)。
- 4つすべてを満たした悩みだけを「事業候補」として社長に上げる。

## 8. 週の流れ(仮)
| 曜日 | 内容 |
|---|---|
| 月 | 5体が1週間分の下書き(note2本・Xスレ・単発投稿)を作る。社長が確認 |
| 火〜金 | 社長が公開。届いた一言をダッシュボードに登録 |
| 随時 | 一言をくれた人へインタビュー依頼文を下書き→社長が送る |
| 金 | 声を集計し、悩みの共通点・基準の達成状況をレポート |
| 月(次週) | 週次レビューで agent.md を直し、柱の回し方を見直す |

## 9. 確認する数字
投稿数 / 一言の数 / インタビュー実施数 / 声の累計(10人まで) / 悩みの共通点の最多件数 / 4基準の達成状況

## 10. 作るもの(確認後に作る)
| 順 | 作るもの | 内容 |
|---|---|---|
| 1 | 発信部の調整 | 柱の回し方、note2本・X毎日の下書き、末尾の導線と一問の差し込み |
| 2 | 声の登録 | ダッシュボードに貼り付けフォーム。判別コード化、悩みタグ、インタビュー状況 |
| 3 | インタビュー依頼文 | 声ごとのDM下書き(送信は社長) |
| 4 | 集計と判断 | リサーチ部が悩みを集計し、4基準を判定。事業候補を要確認に上げる |
| 5 | ダッシュボード | 流れの数字、10人までの進み具合、4基準の達成状況の表示 |
| 6 | 自動化 | 毎週月曜に下書き依頼を自動作成、金曜に集計レポート、10人到達で通知 |

## 11. 仮に決めたこと(違えば直す)
- 3本柱の回し方(柱1を週2本など)
- 「3人以上」の基準
- 週の曜日割り
- 声の記録項目
- 4週間後に、基準・頻度・柱を見直す

## 12. 気をつけること
- 読者像が広いので、悩みが散らばりやすい。同じ悩みが出ない場合は、4週間後に読者像を絞る。
- note週2本とX毎日は量が多い。下書きの確認と公開が社長の負担になるため、確認は月曜にまとめる。
- X・noteの本文に、他人の発言や個人が特定できる情報を載せない。
